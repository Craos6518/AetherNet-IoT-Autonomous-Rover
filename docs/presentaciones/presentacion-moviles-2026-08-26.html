⏱ 0:40 – 1:20 · Aplicación Móvil

Bloque 2 · El proyecto en la App nativa

AetherControl: la interfaz humana de AetherNet

📱 App nativa Android ⚙️ Domótica + Control de acceso + Robot todo en red local — Wi-Fi + BT clásico SPP
“La App se llama AetherControl y es la interfaz humana de todo el sistema: desde el celular el usuario ve sensores en tiempo real, abre la puerta con PIN, maneja el robot con un joystick virtual, y recibe alertas de intrusión — todo funcionando en red local (Wi-Fi), y si se cae el Wi-Fi, cambia automático a Bluetooth clásico.”

🛠 Stack tecnológico

  • Kotlin: todo el código de la app
  • Compose: pantallas reactivas: dashboard, joystick, PIN, alertas
  • MVVM: separación limpia, testeable, ciclo de vida correcto
  • Coroutines + Flow: MQTT/WebSocket en background, UI nunca se traba
  • Hilt: ViewModels, Repositorios, Clientes MQTT/Bluetooth
  • MQTT: tiempo real con backend y gateway
  • Bluetooth SPP: contingencia si Wi-Fi falla

📱 Funcionalidades núcleo (BDD)

  • Dashboard: Compose + StateFlow observando Repository (MQTT)
  • Joystick: PointerInput + drag gestures → vectores X/Y [-1,1] → throttle 50ms → MQTT control/rover/cmd
  • PIN: Compose LazyColumn numérico → MQTT access/door/unlock
  • Alerta: FCM local / NotificationManager + prioridad HIGH
  • Fallback BT: BluetoothAdapter + BluetoothSocket (RFCOMM/SPP)

U3: Back Móvil (Xamarin.Forms, MVVM, Emuladores) MVVM nativo: ViewModel + StateFlow + Repository + DI (Hilt), Emulador + Device físico 🟡 Repository unificado (MQTT + Bluetooth), ViewModel por pantalla, tests unitarios
U4: Datos y Entorno (REST/JSON, APIs, Hardware, Permisos, Multiplataforma) MQTT/WebSocket + Bluetooth SPP (RF-1.3) + Permisos runtime Android 12+ 🟡 Cliente MQTT (reconexión, QoS), Módulo Bluetooth SPP, Pantalla permisos

✅ El syllabus original menciona Xamarin/.NET/C#, pero los objetivos de aprendizaje (MVVM, UI reactiva, consumo de servicios, hardware/permisos, emuladores) son los mismos. Compose es 100% FOSS, requisito del proyecto integrador.

⏱ 2:30 – 3:30 · Funcionalidades

Funcionalidades núcleo con criterios BDD medibles

📊 Dashboard Telemetría

Ve distancia robot, estado puerta, sensores, alertas — en vivo. Compose + StateFlow observando Repository (MQTT)

Criterio aceptación: Dadohay lectura UI se actualiza <200ms

🎮 Joystick Virtual

Arrastra dedo → robot se mueve en esa dirección/velocidad. PointerInput + drag gestures → vectores X/Y [-1,1] → throttle 50ms → MQTT control/rover/cmd

Criterio aceptación: Dadoarrastra comando enviado cada 50ms máx

🔐 PIN Cerrojo

Teclado numérico en pantalla → envía "abrir" → puerta abre (servo) + LED verde. Compose LazyColumn numérico → MQTT access/door/unlock

Criterio aceptación: DadoPIN correcto + # servo 90° + LED verde (HU-01)

🚨 Alerta Intrusión

Notificación push + vibración + sonido + banner rojo si láser se corta. FCM local / NotificationManager + prioridad HIGH

Criterio aceptación: Dadoláser interrumpido notificación <2s (HU-02)

🔁 Fallback Bluetooth

Si Wi-Fi cae → botón "Modo Bluetooth" → conecta a Arduino Nano (HC-06) → control básico. BluetoothAdapter + BluetoothSocket (RFCOMM/SPP)

Criterio aceptación: Dadoactiva BT comandos llegan a Nano (RF-1.3)
