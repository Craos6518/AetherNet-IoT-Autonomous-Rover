⏱ 0:40 – 1:20 · Arquitectura

Arquitectura AetherNet: 5 subsistemas reales

📱 App Móvil

Kotlin + Jetpack Compose (UI declarativa), MVVM, Hilt, MQTT (Paho), Bluetooth SPP (RFCOMM/SPP). Interfaz: dashboard, joystick, PIN, alertas. Todo en red local (Wi-Fi), contingencia BT clásica.

🖥 Backend Local

FastAPI + PostgreSQL + Mosquitto MQTT (Docker Compose). API REST, base de datos de eventos, broker de mensajes tiempo real. 3 contenedores en red interna, volúmenes persistentes, healthchecks.

🌐 Gateway ESP32

C++ (Arduino CLI), Wi-Fi + Radio 2.4GHz (nRF24L01) + Puerto serie (UART). Puente entre sensores y la red local. Comunicación UART ↔ Radio ↔ Puerto serie.

🔧 Controlador MEGA

C++ (Arduino IDE), Teclado 4x4, Servomotor MG90S, Láser KY-008, LED RGB, Relés. Cerrojo electrónico, trampa láser, control de relés.

🚜 Rover UNO

C++ (Arduino UNO), Motores L298N, Ultrasonido HC-SR04, Sensores IR TCRT5000, Radio nRF24L01. Navegación por radiofrecuencia, evasión de obstáculos, anti-caída.

📊 Estadística

Python (Pandas, SciPy) / R. Filtro EMA, Prueba t-Student, Análisis Weibull. Aplicados a sensores reales. KPI: Precisión del Filtro Estadístico > 85% (PRD §5).

Pregunta probable

“DevOps no tiene enfoque en hardware, ¿no?”

Respuesta

Correcto. DevOps cubre la infraestructura y el ciclo de vida del software, pero en AetherNet el hardware es el punto de partida: sin firmware compilado y comunicando microcontroladores, no hay CI/CD que valer. El hardware es la base sobre la que reposan todas las demás áreas.
